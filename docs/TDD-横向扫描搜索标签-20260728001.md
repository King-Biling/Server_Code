## 2. 背景与目标

### 2.1 问题描述

在编队拼接（重构）实验中，小车从离散状态进入直线对接准备阶段（PREPARING → READY → ASSEMBLING → GUIDING）后，由于定位系统存在累积误差，小车到达预对接位置时可能带有横向偏移。该横向偏移导致摄像头视野偏离前车 AprilTag，制导控制器持续无 Tag 可锁定，小车停留在原位不动，无法自动完成对接。

**V2.0 新增问题：** 原自动扫描逻辑中，识别到Tag后会自动停止扫描，但在准备阶段即使识别到标签也存在左右运动，先后顺序或逻辑混乱。需要人工控制扫描的启停时机。

### 2.2 目标

在制导阶段（GUIDING）无 Tag 时，驱动小车执行周期性横向左右移动（扫描），扩大摄像头搜索范围，直至重新捕获 AprilTag，随后自动切换回正常 P 控制对接流程。

**V2.0 新增目标：** 支持手动启停横向扫描，由人工确认何时开启左右扫描和何时结束，避免自动逻辑混乱导致识别到标签后仍有左右运动。

### 2.3 约束

- 不修改车端固件协议（GUIDE 指令的 VY 字段已支持横向速度下发）
- 扫描速度须低于正常行驶速度，避免冲击或失控
- 扫描超时后须安全停车，不得无限扫描
- 自动模式下捕获 Tag 后须立即停止扫描，无缝切换回制导控制
- **手动模式下 Tag 检测不自动停止扫描**，由人工决定何时停止

## 3. 系统架构

### 3.1 整体数据流

```
                          视觉主循环 (vision.py)
                               │
                     PoseEstimator.process_frame()
                               │
                    ┌──────────┴──────────┐
                    │  有 Tag              │  无 Tag
                    ▼                     ▼
         update_guide_controller()   update_guide_controller()
         has_tag=True                has_tag=False
                    │                     │
                    ▼                     ▼
         GuideController               GuideController
         .update_pose_error()          .update_pose_error()
                    │                     │
                    ▼                     ▼
         _calculate_guide_velocity()  _calculate_guide_velocity()
                    │                     │
                    ├─ 手动扫描模式 ──→  _calculate_scan_velocity()
                    │  (scan_manual_override=True)  → (0, scan_vy, 0, 0)
                    │  即使有Tag也继续扫描
                    │
                    ├─ 自动模式+有Tag ──→ 正常 P 控制
                    │                     → (vx, vy, vz, 0)
                    │
                    └─ 自动模式+无Tag ──→ _calculate_scan_velocity()
                                          → (0, scan_vy, 0, 0)
                               │
                               ▼
                    _send_guide_command()
                               │
                               ▼
                    [R,GUIDE,CARn,VX=,VY=,VZ=,DONE=0]
                               │
                               ▼
                    车端 handle_guide() → vel_solver_set_manual_speed()
```

### 3.2 状态机扩展

原制导阶段无 Tag 时直接返回 `(0, 0, 0, 0)` 停车。扩展后：

```
GUIDING 状态
  │
  ├─ 手动扫描模式 (scan_manual_override=True)
  │    └─ scan_active=True ──→ 横向扫描（Tag检测不停止）
  │         │
  │         ├─ elapsed < SCAN_MAX_DURATION
  │         │    ├─ phase ∈ [0, T/2)  →  scan_vy = +SCAN_SPEED（向右）
  │         │    └─ phase ∈ [T/2, T)  →  scan_vy = -SCAN_SPEED（向左）
  │         │
  │         └─ elapsed ≥ SCAN_MAX_DURATION ──→ 停止扫描，复位手动模式
  │
  ├─ 自动模式 + 有 Tag ──→ 正常 P 控制（前进+横向+航向）
  │
  └─ 自动模式 + 无 Tag ──→ 横向扫描模式
                           │
                           ├─ scan_active=False ──→ 启动扫描，记录 scan_start_time
                           │
                           ├─ scan_active=True
                           │    ├─ elapsed < SCAN_MAX_DURATION
                           │    │    ├─ phase ∈ [0, T/2)  →  scan_vy = +SCAN_SPEED（向右）
                           │    │    └─ phase ∈ [T/2, T)  →  scan_vy = -SCAN_SPEED（向左）
                           │    │
                           │    └─ elapsed ≥ SCAN_MAX_DURATION ──→ 停止扫描，停车等待
                           │
                           └─ 连续 SCAN_TAG_LOCK_FRAMES 帧检测到 Tag
                                ──→ scan_active=False，切换回正常 P 控制
```

## 4. 模块设计

### 4.1 配置参数（config.py）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `SCAN_ENABLED` | bool | `True` | 横向扫描总开关 |
| `SCAN_SPEED` | float | `0.03` | 扫描横向速度 (m/s) |
| `SCAN_AMPLITUDE` | float | `0.08` | 扫描单侧幅度 (m)，即左右各移 8cm |
| `SCAN_HALF_PERIOD` | float | `2.0` | 扫描半周期 (秒)，左右各 2 秒 |
| `SCAN_TAG_LOCK_FRAMES` | int | `3` | 连续检测到 Tag 的帧数，确认锁定后停止扫描 |
| `SCAN_MAX_DURATION` | float | `30.0` | 扫描最大持续时间 (秒)，超时放弃扫描 |

**参数关系：**

- 完整扫描周期 = `2 × SCAN_HALF_PERIOD` = 4 秒
- 单侧最大位移 = `SCAN_SPEED × SCAN_HALF_PERIOD` = 0.03 × 2.0 = 0.06 m = 6 cm
- `SCAN_AMPLITUDE` 为设计参考值，实际位移由速度和时间决定

### 4.2 状态字段（state.py）

`reconstruct_state["scan_state"]` 字典，键为 `car_id`，值为：

| 字段 | 类型 | 说明 |
|------|------|------|
| `active` | bool | 扫描是否正在运行 |
| `start_time` | float | 扫描启动时间戳 (time.time()) |
| `direction` | int | 当前扫描方向：+1 向右，-1 向左 |
| `tag_lock_count` | int | 扫描中连续检测到 Tag 的帧数 |

`reconstruct_state["scan_manual_override"]` 标量：

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `scan_manual_override` | bool | `False` | 手动扫描覆盖开关：True 时由人工控制启停，Tag 检测不自动停止扫描 |

`reconstruct_state["guide_velocity"][car_id]` 扩展字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `scan_active` | bool | 下发该帧时扫描是否激活 |

### 4.3 核心类：GuideController（guide.py）

#### 4.3.1 新增实例属性

| 属性 | 类型 | 初始值 | 说明 |
|------|------|--------|------|
| `scan_active` | bool | `False` | 横向扫描是否正在运行 |
| `scan_start_time` | float | `0` | 扫描启动时间 |
| `scan_direction` | int | `1` | 扫描方向：+1 向右，-1 向左 |
| `scan_tag_lock_count` | int | `0` | 扫描中连续检测到 Tag 的帧数 |

#### 4.3.2 新增方法

**`start_scan_manual(self) -> bool`**

手动启动横向扫描（由 HTTP 接口调用）。

算法伪代码：

```
1. 若 SCAN_ENABLED == False，返回 False
2. 若 scan_manual_override==True 且 scan_active==True，返回 False（已在运行）
3. scan_active=True, scan_start_time=now, direction=1, tag_lock_count=0
4. scan_manual_override=True
5. 调用 _update_scan_state()
6. 返回 True
```

**`stop_scan_manual(self) -> bool`**

手动停止横向扫描（由 HTTP 接口调用）。

算法伪代码：

```
1. scan_active=False, tag_lock_count=0
2. scan_manual_override=False
3. 调用 _update_scan_state()
4. 返回 True
```

**`_calculate_scan_velocity(self) -> float`**

生成三角波横向扫描速度，区分手动/自动模式。

算法伪代码：

```
输入: self.last_has_tag, self.scan_active, self.scan_start_time, scan_manual_override
输出: scan_vy (m/s)

1. 若 SCAN_ENABLED == False，返回 0.0

2. 读取 scan_manual_override

3. 【手动模式】若 scan_manual_override == True:
   a. 若 scan_active == False，启动扫描
   b. 超时检查: elapsed > SCAN_MAX_DURATION → 停止扫描，复位 manual_override，返回 0.0
   c. 三角波方向切换，返回 direction × SCAN_SPEED
   （注意：手动模式下不检查 Tag 锁定，不自动停止）

4. 【自动模式】Tag 锁定检测：
   - 若 last_has_tag == True:
       scan_tag_lock_count += 1
       若 scan_tag_lock_count >= SCAN_TAG_LOCK_FRAMES:
           停止扫描，返回 0.0
   - 否则:
       scan_tag_lock_count = 0

5. 若已有 Tag 且有位姿误差，无需扫描，返回 0.0

6. 若 scan_active == False:
       启动扫描: scan_active=True, scan_start_time=now, direction=1

7. 超时检查:
   - 若 (now - scan_start_time) > SCAN_MAX_DURATION:
       停止扫描，返回 0.0

8. 三角波方向切换:
   - elapsed = now - scan_start_time
   - phase = elapsed % (2 × SCAN_HALF_PERIOD)
   - direction = +1 若 phase < SCAN_HALF_PERIOD，否则 -1

9. 返回 direction × SCAN_SPEED
```

**`_update_scan_state(self)`**

将扫描状态写入 `state.reconstruct_state["scan_state"][car_id]`，供监控界面和 API 读取。

#### 4.3.3 修改方法

**`_calculate_guide_velocity(self)`**

原逻辑：无 Tag 时返回 `(0, 0, 0, 0)` 停车。

新逻辑（V2.0）：

```
【手动扫描模式优先判断】
若 scan_manual_override==True 且 scan_active==True:
    scan_vy = _calculate_scan_velocity()
    若 |scan_vy| > 0:
        返回 (0.0, scan_vy, 0.0, 0)    ← 手动扫描，即使有Tag也继续
    否则:
        返回 (0.0, 0.0, 0.0, 0)

【自动模式原有逻辑】
若 (not last_has_tag) 或 (距上次 Tag > 0.5s):
    reached_hold_count = 0
    scan_vy = _calculate_scan_velocity()
    若 |scan_vy| > 0:
        返回 (0.0, scan_vy, 0.0, 0)    ← 横向扫描，不前进
    否则:
        返回 (0.0, 0.0, 0.0, 0)        ← 停车等待

...后续正常P控制逻辑不变...
```

**`_guidance_loop(self)`**

原逻辑：`last_pose_error is None` 时发送 `(0, 0, 0, done=0)`。

新逻辑：

```
若 last_pose_error is None:
    scan_vy = _calculate_scan_velocity()
    _send_guide_command(0, scan_vy, 0, done=0)
```

即进入制导阶段但尚未收到视觉数据时，也启动扫描。

**`stop_guidance(self)`**

新增：重置 `scan_active=False`，`scan_tag_lock_count=0`，调用 `_update_scan_state()`。

## 5. 接口定义

### 5.1 对车端接口

无新增指令。扫描横向速度通过现有 `[R,GUIDE]` 指令的 `VY` 字段下发：

```
[R,GUIDE,CARn,VX=0.000,VY=±0.030,VZ=0.000,DONE=0]
```

车端 `handle_guide()` 已通过 `vel_solver_set_manual_speed(vx, vy, vz)` 正确处理，无需修改。

### 5.2 HTTP 接口（V2.0 新增）

**`POST /api/reconstruct/scan/start`** — 手动启动横向扫描

| 条件 | 说明 |
|------|------|
| 前置条件 | 重构阶段为 `assembling`（拼接中）且有待拼接车辆 |
| 调用对象 | 当前 `waiting_car_id` 对应的 `GuideController` |
| 效果 | `scan_active=True`, `scan_manual_override=True` |
| 返回 | `{success: true, message: "CARn 横向扫描已启动", car_id: "CARn"}` |

**`POST /api/reconstruct/scan/stop`** — 手动停止横向扫描

| 条件 | 说明 |
|------|------|
| 前置条件 | 无（任何时候均可调用） |
| 调用对象 | 遍历所有 `guide_controllers`，停止活跃的扫描 |
| 效果 | `scan_active=False`, `scan_manual_override=False` |
| 返回 | `{success: true, message: "横向扫描已停止"}` |

### 5.3 对监控界面接口

`/api/reconstruct/status` 返回的 JSON 中新增：

```json
"scan_state": {
    "CAR2": {
        "active": true,
        "start_time": 1722140000.123,
        "direction": 1,
        "tag_lock_count": 0
    }
},
"scan_manual_override": true
```

`guide_velocity` 中每车新增 `"scan_active"` 字段。

## 6. 详细流程图

### 6.1 扫描启动与运行时序

```
时间轴 (秒)
0        2        4        6        8       10
│        │        │        │        │        │
├────────┤        ├────────┤        ├────────┤
│  → 右  │        │  → 右  │        │  → 右  │
│        ├────────┤        ├────────┤        │
│        │  ← 左  │        │  ← 左  │        │
│        │        │        │        │        │

scan_vy: +0.03   -0.03   +0.03   -0.03   +0.03  (m/s)

横向位移:  0 → +6cm → 0 → +6cm → 0 → +6cm (三角波)
```

### 6.2 自动模式 Tag 捕获时序

```
帧1: 无Tag → scan_active=True, scan_vy=+0.03
帧2: 无Tag → scan_vy=+0.03
帧3: 无Tag → scan_vy=-0.03 (方向切换)
帧4: 有Tag → scan_tag_lock_count=1, scan_vy=-0.03 (继续扫描)
帧5: 有Tag → scan_tag_lock_count=2, scan_vy=-0.03
帧6: 有Tag → scan_tag_lock_count=3 ≥ SCAN_TAG_LOCK_FRAMES
       → scan_active=False, 切换回正常 P 控制
帧7: 有Tag → 正常制导: vy = GUIDE_P_GAIN_Y × error_y
```

### 6.3 手动模式时序（V2.0 新增）

```
人工操作:  点击"启动扫描"                    点击"停止扫描"
              ↓                                   ↓
时间轴:  ─────┬─────────────────────────────────────┬──────
              │                                     │
scan_manual   False → True                          True → False
scan_active   False → True                          True → False
              │                                     │
              ├─ 即使检测到Tag ──→ 扫描继续         │
              ├─ scan_vy 交替 ±0.03                 │
              └─ 超时30s → 自动停止+复位            │
                                                   └─ 切换回自动模式/正常P控制
```

## 8. 边界条件与错误处理

| 场景 | 处理方式 |
|------|----------|
| 扫描中突然丢失 Tag | 自动模式：`scan_tag_lock_count` 归零，继续扫描；手动模式：不受影响 |
| 扫描超时（>30s） | `scan_active=False`，手动模式同时复位 `scan_manual_override=False`，停车等待 |
| 制导被中止（abort） | `stop_guidance()` 重置扫描状态 |
| `SCAN_ENABLED=False` | `_calculate_scan_velocity()` 直接返回 0.0，行为与原系统一致 |
| 多车同时制导 | 每车独立 `GuideController` 实例，扫描状态互不干扰 |
| 扫描中收到 `done=1` | `target_reached=True` 后停止所有运动，扫描自然终止 |
| 非拼接阶段点击启动扫描 | 返回错误 "仅在拼接阶段可启动扫描" |
| 手动扫描期间检测到Tag | 不自动停止扫描，继续左右移动，由人工决定何时停止 |

## 9. 性能分析

| 指标 | 值 | 说明 |
|------|-----|------|
| 扫描横向速度 | 0.03 m/s | 远低于限幅 0.105 m/s，安全可控 |
| 单侧最大位移 | 6 cm | 小于摄像头视野宽度，足以覆盖定位误差 |
| 扫描周期 | 4 秒 | 左右各 2 秒，搜索效率与平稳性平衡 |
| 制导循环频率 | 20 Hz | 扫描速度在每 50ms 周期下发，响应及时 |
| Tag 锁定延迟（自动模式） | ≤3 帧 × 50ms = 150ms | 连续 3 帧确认，去抖防误判 |
| 最大扫描时长 | 30 秒 | 约 7.5 个完整扫描周期，覆盖大范围偏移 |

## 13. 附录：扫描速度参数速查

# 横向扫描参数（进入制导阶段后持续无Tag时，小车左右横移搜索标签）

SCAN_SPEED = 0.03                 # 扫描横向速度 (m/s)      ← 左右移动速度
