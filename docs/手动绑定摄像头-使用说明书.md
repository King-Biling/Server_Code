# 手动绑定摄像头 — 使用说明书

> 版本：v1.3  
> 更新日期：2026-07-28  
> 适用系统：智能群体机器人协同控制实验平台

---

## 1. 功能概述

手动绑定摄像头功能用于将系统检测到的 USB 摄像头逐个分配给对应的小车（ROBOT#1 ~ ROBOT#4）。系统逐个打开摄像头并截取画面展示，操作人员根据画面内容直接选择对应的小车进行绑定。

### 核心特性

| 特性 | 说明 |
|------|------|
| 逐摄像头展示 | 每次只显示一个摄像头的实时画面，操作人员确认后再切换下一个 |
| 小车选取 | 下拉选择当前画面对应的小车，已绑定的自动禁用 |
| 画面刷新 | 画面未出来或画面异常时，点击刷新重新抓帧 |
| 跳过切换 | 当前摄像头不需要绑定时，跳过并自动切换到下一个 |
| 自动推进 | 确认绑定后自动切换到下一个摄像头画面 |
| 自动跳过内置摄像头 | 系统自动排除配置中指定的摄像头索引（如笔记本内置摄像头），无需手动跳过 |
【bin的电脑本机摄像头为摄像头1，即在car_vision_system.py中"SKIP_CAMERA_INDICES": [1],#修改这个列表即可控制跳过哪些摄像头索引，如 [0, 1] 跳过索引 0 和 1，[] 不跳过任何摄像头。】
| 频道映射表 | 弹窗内展示"频道→小车"的静态映射关系，方便操作人员对照 |
| 绑定关系实时显示 | 右侧面板实时展示已完成的绑定关系 |

## 2. 界面说明

### 2.1 视觉监控模块

视觉监控模块位于右侧控制面板中，采用与其他模块一致的折叠面板样式，包含"摄像头绑定"和"视觉监控"两个子区域：

```
┌─ 视觉监控 ──────────────────────────────────────────────┐
│                                                          │
│  摄像头绑定                                               │
│  [手动绑定摄像头]                                         │
│  绑定状态: 未绑定                                         │
│                                                          │
│  视觉监控                                                 │
│  [▼ 选择小车        ]                                    │
│  [打开监控]                                               │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

| 元素 | 说明 |
|------|------|
| 手动绑定摄像头 | 打开手动绑定弹窗，进入逐摄像头绑定流程 |
| 绑定状态 | 实时显示当前绑定情况，如"绑定状态: 已绑定 2 路 (R#1→Cam0, R#2→Cam2)"或"绑定状态: 未绑定" |
| 选择小车 | 下7下拉选择要监控的小车 |
| 打开监控 | 打开选定小车的 MJPEG 视觉监控窗口 |

#### 左侧 — 画面预览区

| 元素 | 说明&说明 |
|------|------|

| 实时画面 | 当前摄像头的抓帧画面（640x480，JPEG 质量 85），画面清晰可辨 |

#### 右侧 — 控制面板区

| 元素 | 说明 |

| 刷新画面 | 重新打开当前摄像头抓帧，适用于画面未出现或画面异常的情况 |
| 取消 | 终止整个手动绑定流程 |
| 已绑定关系 | 实时显示已完成的绑定，如"R#1 → 摄像头 0" |
| 频道映射表 | 展示系统配置的"频道→小车"静态映射关系及当前绑定状态 |

## 3. 操作流程

### 3.1 标准绑定流程

```
开始
  │
  ▼
点击"手动绑定摄像头"按钮
  │
  ▼
系统扫描所有可用摄像头 ────── 无摄像头 ──→ 提示"未发现摄像头"，流程结束
  │
  ▼
显示第 1 个摄像头画面
  │
  ▼
┌──────────────────────────────────┐
│  画面是否正确显示？               │
│  ├─ 否 → 点击"刷新画面"         │
│  └─ 是 → 继续                    │
│                                   │
│  当前画面属于哪辆小车？           │
│  ├─ 不需要绑定 → 点击"跳过"      │
│  └─ 属于某车 → 选择小车 → 点击"确认绑定" │
│                                   │
│  自动切换到下一个摄像头           │
└──────────────────────────────────┘
  │
  ▼
所有摄像头处理完毕
  │
  ▼
系统应用绑定结果，启动视觉检测
  │
  ▼
完成
```

### 3.2 典型操作示例

**场景：3 个 USB 摄像头接入，分别对应 ROBOT#1、ROBOT#2、ROBOT#3**

1. 在视觉监控模块中点击 **[手动绑定摄像头]** 按钮
2. 弹窗打开，显示摄像头 0 的画面
3. 观察画面，确认显示的是 ROBOT#1 的图传画面
4. 下拉选择 **ROBOT#1**，点击 **[确认绑定]**
5. 自动切换到摄像头 1 的画面
6. 观察画面，确认显示的是 ROBOT#2 的图传画面
7. 下拉选择 **ROBOT#2**，点击 **[确认绑定]**
8. 自动切换到摄像头 2 的画面
9. 观察画面，确认显示的是 ROBOT#3 的图传画面
10. 下拉选择 **ROBOT#3**，点击 **[3确认绑定]**
11. 全部摄像头处理完毕，弹窗显示"绑定流程已完成"
12. 视觉监控模块状态更新为"绑定状态: 已绑定 3 路 (R#1→Cam0, R#2→Cam1, R#3→Cam2)"

### 3.3 特殊情况处理

| 情况 | 操作 |
|------|------|
| 画面黑屏/无画面 | 点击 **[刷新画面]** 重新抓帧；若多次刷新仍无画面，可能是摄像头未就绪，点击 **[跳过]** |
| 画面显示内置摄像头（笔记本自带） | 系统已自动排除配置中指定的内置摄像头索引，如仍出现可通过 **[跳过]** 跳过 |
| 同一摄像头需要重新绑定 | 取消当前流程，重新点击 **[手动绑定摄像头]** 开始 |
| 绑定过程中想放弃 | 点击 **[取消]** 终止流程，已绑定的结果不会被应用 |

## 4. 频道映射关系

系统预设的 OSD 频道与小车对应关系如下：

| OSD 频道 | 对应小车 | 说明 |
|----------|----------|------|
| A8 | ROBOT#1 | CAR1 的图传接收机频道 |
| E1 | ROBOT#2 | CAR2 的图传接收机频道 |
| A1 | ROBOT#3 | CAR3 的图传接收机频道 |
| R8 | ROBOT#4 | CAR4 的图传接收机频道 |

> 频道映射关系定义在 `Car_vision_system/car_vision_system.py` 的 `CONFIG["CHANNEL_MAP"]` 中，如需修改请编辑该配置。

手动绑定弹窗中的"频道映射表"会展示此映射关系及当前绑定状态，供操作人员对照参考。**系统不会自动识别画面中的频道**，绑定完全由操作人员根据画面内容手动决定。

## 5. API 接口说明

手动绑定功能通过以下 REST API 实现：

| 接口 | 方法 | 请求体 | 响应 | 说明 |
|------|------|--------|------|------|
| `/api/vision/bind/manual/start` | POST | 无 | `{success, message}` | 启动手动绑定流程 |
| `/api/vision/bind/manual/status` | GET | 无 | `{active, finished, total_cameras, current_index, current_camera, current_frame, bound_so_far}` | 查询当前绑定状态 |
| `/api/vision/bind/manual/confirm` | POST | `{car_id: "CAR1"}` | `{success, message, finished, current_index, total_cameras}` | 确认绑定并自动切换下一个 |
| `/api/vision/bind/manual/skip` | POST | 无 | `{success, message, finished, current_index, total_cameras}` | 跳过当前摄像头 |
| `/api/vision/bind/manual/refresh` | POST | 无 | `{success, message, frame}` | 刷新当前摄像头画面 |
| `/api/vision/bind/manual/cancel` | POST | 无 | `{success, message}` | 取消绑定流程 |
| `/api/vision/channel-map` | GET | 无 | `{success, channel_map, reverse_map, car_to_channel, bound_cameras}` | 获取频道映射关系 |

## 6. 技术实现说明

### 6.1 后端状态管理

手动绑定流程的状态存储在 `server_app/state.py` 的 `manual_bind_state` 字典中：

- `active` — 绑定流程是否激活
- `cameras` — 扫描到的摄像头列表（含索引、分辨率）
- `current_index` — 当前正在处理的摄像头在列表中的下标
- `current_frame_b64` — 当前摄像头的画面（base64 JPEG，640x480，质量 85）
- `bound_so_far` — 已绑定的映射 `{CAR_ID: CAMERA_INDEX}`
- `finished` — 流程是否完成

### 6.2 摄像头抓帧

每次展示/刷新画面时，后端通过 `DeviceBinder._open_camera()` 打开指定摄像头，抓取若干帧后取最佳帧。**不进行任何 OSD 频道识别或模板匹配**，仅截取原始画面。画面以 640x480 分辨率、JPEG 质量 85 编码为 base64 传输到前端。抓帧完成后立即释放摄像头，避免占用 USB 总线。

### 6.3 绑定完成后的应用

当所有摄像头处理完毕（全部确认绑定或跳过）后，系统调用 `DeviceBinder.manual_bind()` 将 `bound_so_far` 中的映射正式应用，写入 `state.vision_state["bound_cameras"]`，并启动第一个已绑定摄像头的视觉检测循环。

### 6.4 前端轮询

弹窗打开后，前端以 800ms 间隔轮询 `/api/vision/bind/manual/status` 接口，实时更新画面和状态。确认绑定/跳过后额外触发一次即时轮询，减少切换延迟。

## 7. 注意事项

1. **USB 总线共享**：系统使用共享 USB 总线，同一时刻只能打开一路摄像头。手动绑定流程中每次只打开一个摄像头抓帧，抓完即释放，不会与视觉检测循环冲突。
2. **画面延迟**：摄像头切换后需要约 0.3~0.5 秒的 USB 冷却时间，首次画面可能出现短暂黑屏，点击"刷新画面"即可。
3. **内置摄像头自动排除**：系统通过 `Car_vision_system/car_vision_system.py` 中 `CONFIG["SKIP_CAMERA_INDICES"]` 配置自动跳过指定的摄像头索引。当前默认值为 `[1]`，即跳过索引 1（笔记本内置摄像头）。如需调整，修改该配置即可，例如 `[0, 1]` 跳过索引 0 和 1，`[]` 不跳过任何摄像头。
4. **绑定顺序**：手动绑定的顺序不影响最终结果，可以按任意顺序绑定。
5. **重复绑定**：同一辆小车只能绑定一个摄像头。如果需要更换绑定，需取消当前流程后重新开始。
6. **画面清晰度**：弹窗画面以 640x480 分辨率传输，若画面仍不够清晰，可点击"刷新画面"重新抓取最新帧。
7. **纯手动绑定**：系统不会自动识别画面中的 OSD 频道或建议绑定到某辆小车，操作人员需根据画面内容自行判断并选择对应的小车。
