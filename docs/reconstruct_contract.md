重构模式服务器端契约（草案）
================================

目标概述
- 明确服务器与小车在重构（reconstruct）模式下的通信约定，避免协议理解不一致导致准备卡住、图像同时上报、掉线误判和时序死锁。
- 服务器为调度者，小车为执行者；服务器负责顺序、重试、超时与重组判断。

1. 总体原则
- 服务器是重构流程的调度者，小车为执行者，双方按约定消息交互。
- 准备阶段（PREP）必须保证后车可见前车状态，尽量先保持宽松拓扑以确保可见性。
- 拼接阶段尽量串行：同一时刻只允许 1 辆车主动发送完整帧的图像（并发上限建议为 1）。
- 服务器收到某辆车图像后应立即为该车生成并下发 `GUIDE`，不应等候其它车辆图像统一处理。
- 把 `PREP_OK`、`STEP_OK`、`STEP_FAIL` 视为阶段性控制信号并记录时间戳（服务器端必须保存每条事件时间）。

2. 推荐时序（高层）
1. 服务器广播 `[R,PREP]`（并保持拓扑为可见性优先）。
2. 服务器尽快广播完整 `ORDER`，例如 `[R,ORDER,CAR1,CAR2,CAR3,CAR4]`（必须为完整序列）。
3. 各车进入 PREP，按自身序号寻找前车状态；达到阈值后回 `PREP_OK`（并包含时间戳）。
4. 服务器等待所有车辆 `PREP_OK`（见第3节重试策略）。
5. 服务器按序逐车下发 `[R,STEP,CARn,POS=HEAD|MID2|MID3|TAIL]`。
6. 被选中的车辆上传 `IMG_META`（文本头）然后一帧的若干个 `IMG_CHUNK`（二进制分片）。
7. 服务器重组并解析图像后向该车下发 `[R,GUIDE,CARn,VX=...,VY=...,VZ=...,DONE=0|1]`（频率建议 50–100 ms）。
8. 若服务器下发 `DONE=1`，该车应减速停车并回 `STEP_OK`。
9. 所有车辆完成后服务器广播 `[R,DONE]` 或启动分离流程。

3. 准备阶段（PREP）要求与服务器责任
- `ORDER` 必须在 `PREP` 后尽快下发，且为完整车辆序列（不能缺车）。
- 准备目标定义为“保持在前车后方固定间距”，不是绝对坐标点。
- 若启用拓扑过滤，必须保证后车仍能收到前车广播（链路可见性）。
- 若某车长时间未回 `PREP_OK`：优先检查是否能收到该车的前车状态（不要直接判定该车故障）。
推荐服务器实现：
- 维护 `prep_waiting` 表：按车记录最后一次收到的前车状态时间与自己最后一次 `PREP_OK` 时间。
- 若某车在 3 秒内未回 `PREP_OK`，先发送一次重试型 `PREP` 或重新广播 `ORDER`，而非马上剔除。
- 若场地/视觉条件需调整排序，服务器必须整体更新 `ORDER`（不允许只局部改动）。

4. 图像上报协议（必须严格）
消息构成：
- 文本头：`IMG_META`（必须先发，包含 SEQ/W/H/LEN 等元信息）。
- 二进制分片：`IMG_CHUNK`（每个分片仅携带原始 JPEG/图像字节，不应做 Base64 或二次编码）。
核心规则：
1. `IMG_META` 必须先到达，之后开始发送 `IMG_CHUNK`。
2. `IMG_CHUNK` 发送原始二进制，服务器接收时应先以二进制安全方式判定边界（例如按 header 与首个 `\n` 分隔），避免先行 UTF-8 解码破坏 JPEG 数据。
3. 服务器以 `(car_id, SEQ)` 作为帧命名空间，不允许跨车混拼。
4. 按 `SEQ` + `IDX` + `TOT` + `LEN` 重组同一帧：
	 - 若发现 `IDX` 不连续、`TOT` 与 `IDX` 不匹配或 `LEN` 不一致、或 `SEQ` 在中途变化，应弃掉该帧并请求车端重发（返回错误/重发指令）。
5. 建议 `IMG_META` 字段至少包含：
	 - `SEQ`：帧序号（单调或可回绕，但序号变化策略需一致）。
	 - `W`/`H`：图像尺寸。
	 - `LEN`：整帧字节长度（完整 JPEG 字节数）。
	 - `IDX`/`TOT`/`SZ`：当前分片索引、总分片数、当前分片字节长度。
6. 超时与重发：
	 - 服务器为一帧设置重组超时（建议 300–800 ms 起始，视网络与丢包率调整）。
	 - 超时或分片错误则丢弃该帧并通知车端重新发送（或请求重发当前 SEQ）。

5. `GUIDE` 指令约定
- `GUIDE` 仅下发给正在拼接的单车（标注 `CARn`）。
- `VX/VY/VZ` 为本地速度或控制量，方向约定需与车端一致（双方必须在接入前确认方向与单位）。
- `DONE=1`：服务器认为该车阶段完成。车端需立即减速停车并回 `STEP_OK`。
- `DONE=0`：继续执行，车端不得提前结束该阶段。
- 若服务器较长时间未下发 `GUIDE`，车端进入超时保护；因此服务器应保持定期刷新。
服务器节拍建议：
- 每 50–100 ms 刷新一次 `GUIDE`（频率与网络负载折中）。
- 当视觉暂时无解时也应下发保活速度（如小速度或零速度），而不是完全中止下发。

6. 拓扑策略（Topology）
- PREP 阶段：建议使用全连通或至少保证链路可见性（保证每辆车能看到其前车）。
- STEP 阶段：仍应保证前车可见性，以便实时读取前车状态并在需要时重试 PREP。
- 仅在确认不再依赖全局状态后才切换更严格的拓扑过滤。
最低要求：
- 每辆车必须能接收到其前车的广播状态。
- `ORDER` 与拓扑矩阵必须一致，不能出现顺序包含某前车但拓扑把该前车屏蔽的情况。

7. 失败处理与恢复策略
- 收到 `STEP_FAIL`：
	- 暂停该车拼接，停止下发 `GUIDE` 给该车。
	- 图像环节任何失败都统一上报 `STEP_FAIL`，不再请求 `IMG_RESEND`。
	- 服务器检测到 `STEP_FAIL` 后，重新下发 `[R,STEP,CARn,...]` 触发重试；车端重新进入该车的准备/拼接流程。
	- 准备超时需检查拓扑与前车状态。
- 若某车离线：
	- 标记该车为不可用并临时从 `ORDER` 中移除，重新计算序列或按策略跳过。
- 严格记录每次失败原因与时间戳，便于现场回放与诊断。

8. 服务器实现最小检查清单（必须实现）
- PREP 发送后，至少等待每车并记录 `PREP_OK`（含时间戳）。
- STEP 必须逐车串行下发（默认串行，必要时可配置并发策略）。
- 图像严格按 `IMG_META -> IMG_CHUNK` 重组，校验 `SEQ/IDX/TOT/LEN`。
- `GUIDE` 必须持续刷新直至 `DONE=1`（并记录最后下发时间）。
- 记录每辆车的最后心跳、`PREP_OK`、`STEP_OK`、`STEP_FAIL` 时间（用于 `prep_waiting` 与故障判断）。

9. 与当前车端的约定（已知车端行为）
- 车端准备阶段依赖前车状态。
- 拼接阶段按顺序错峰上报图像，减少冲突。
- `GUIDE` 超时触发车端失败保护。
- 结束拼接后车端立刻停车并上报结果（`STEP_OK`/`STEP_FAIL`）。

10. 建议的服务器实现要点（工程细节）
- 接收逻辑：
	- UDP 接收时优先二进制安全处理：若数据包含 `IMG_CHUNK` 标识并且存在 `\n`（头尾分隔），按 header_end = data.find(b'\n') 分割 header（UTF-8 decode）与 payload（二进制）；
	- 仅在非二进制路径下才把整包当文本 decode，避免破坏 JPEG 数据。
- 图像重组：
	- 以 `(car_id, SEQ)` 为会话键名；
	- 限制 per-car 并发会话窗口（例如 1–3）并通过最旧会话回收避免内存泄漏；
	- 丢帧策略：若校验失败立即丢弃并回执车端请求重发。
- PREP 管理：
	- 实现 `prep_waiting` 表，记录每辆车前车状态时间并用于重试决策；
	- 若某车 3 秒内未 `PREP_OK`，优先重试 PREP/ORDER。
- GUIDE 下发：
	- 对正在拼接的车维持一个定时刷新任务（50–100ms），确保超时保护不被触发。
- 日志与监控：
	- 必须记录每条 PREP/STEP 事件的时间戳、每帧重组开始/完成/失败时间、最后心跳时间，便于回放与诊断。

11. 现场联调建议（检查项）
- 在开始联调前确认：
	- `ORDER` 与拓扑矩阵一致；
	- 车端 `GUIDE` 方向与单位与服务器一致；
	- AprilTag/视觉标签字典一致（若用 AprilTag，请确认 DICT 类型）。
- 联调步骤：
 1. 广播 `[R,PREP]` 并确认每辆车能接收前车状态（观察 `prep_waiting`）。
 2. 广播 `ORDER` 并确认每车能回复 `PREP_OK`；
 3. 对单台车执行 STEP-上传图像，检查服务器能正确按 `(SEQ,IDX,TOT,LEN)` 重组并下发 `GUIDE`；
 4. 逐车重复 STEP，确认串行流程与 `DONE` 语义生效。
- 调整参数（建议起点）：
	- 图像重组超时：400 ms；
	- per-car 会话窗口：1–3；
	- GUIDE 刷新：50–100 ms；
	- PREP 重试阈值：3 秒。

附：示例消息格式（建议）
- PREP 广播： [R,PREP]
- ORDER 广播： [R,ORDER,CAR1,CAR2,CAR3,CAR4]
- STEP 下发： [R,STEP,CAR2,POS=MID2]
- IMG_META（示例文本头）： IMG_META,SEQ=123,W=640,H=480,LEN=34567,TOT=5
- IMG_CHUNK（二进制包）： IMG_CHUNK,SEQ=123,IDX=1,TOT=5,SZ=8192\n<raw JPEG bytes>
- GUIDE（服务器下发）： [R,GUIDE,CAR2,VX=0.12,VY=0.00,VZ=0.00,DONE=0]
- STEP_OK： [R,STEP_OK,CAR2,SEQ=123]
- STEP_FAIL： [R,STEP_FAIL,CAR2,REASON=TIMEOUT]

结束语
